# Практическое задание: Agent Guardrails (тестирование защит агента)

Ноутбук `Тестирование-agent-guards.ipynb` — задание по защите AI-агента middleware-слоями.

## Что где смотреть

1. Верх ноутбука — демо-ячейки из постановки задания (агенты с Human-in-the-Loop, PII, лимитами вызовов и LLM Guard). Оставлены без изменений: они рассчитаны на окружение преподавателя (нужны `OPENAI_API_KEY`, `TAVILY_API_KEY` и PDF-файлы кейсов).
2. Раздел **«Практическое задание»** (конец ноутбука) — выполненная часть:
   - **Задание 1. PII Detection с собственной функцией** — детекция персональных данных на регулярных выражениях (email, телефоны, карты, паспорт, СНИЛС, имена после маркеров), маскирование и блокировка, проверка до запроса к модели и после ответа; тесты детекции, маскирования, блокировки и граничных случаев.
   - **Задание 2. Анализ безопасности через LLM Guard** — последовательная цепочка из 5 входных сканеров (InvisibleText, Secrets, PromptInjection, Toxicity, BanSubstrings) и 3 выходных (Secrets, Toxicity, Sensitive) в middleware; тесты атак, проверка утечки секрета в ответе, матрица срабатываний по видам атак и анализ результатов (false negatives / false positives, влияние на ответ модели).

## Как запустить практическую часть

- Python 3.12, зависимости: `llm-guard`, `langgraph`, `langchain`, `langchain-mistralai`, `loguru`.
- В окружении нужен `MISTRAL_API_KEY` — модель подхватывается из переменной окружения, в коде ключа нет.
- Ячейки практической части самодостаточны и выполняются сверху вниз без демо-ячеек.

## Результаты

- Детекция и маскирование PII работают на всех проверенных форматах; пропуски и ложные срабатывания разобраны в выводах задания 1.
- Входные атаки (инъекции, невидимые символы, токсичность, секреты) блокируются до вызова модели; секреты и PII в ответе маскируются. Матрица срабатываний и анализ пробелов (языковая граница Toxicity, зависимость BanSubstrings от списка) — в выводах задания 2.
