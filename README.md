# MCP Experiment Lab

Работа по лабораторной «MCP Experiment Lab»: эксперименты с MCP-сервером (FastMCP) по всем восьми заданиям, модификация сервера и агента. Ниже — с чего начать проверку, что где лежит и как запустить. Исходное описание задания сохранено в конце файла без изменений.

## Порядок проверки

1. **`Отчёт.docx`** (та же версия текстом — `Отчёт.md`) — главный документ: результаты всех экспериментов, заполненная таблица транспортов, таблица из 10 экспериментов агента, ответы на вопросы анализа, выводы. Начинать с него.
2. **`logs/`** — протоколы прогонов, по файлу на эксперимент:
   - `exp1_prompt_resources_tools.txt` — задания 1–3 на исходном сервере: prompt на разных входах (простая/сложная тема, пустая, без аргумента, инъекция), чтение ресурсов, поведение `add` и `get_weather`;
   - `exp2_geo_before.txt` — геокодинг (регистр названий, русские названия) и содержимое ресурсов до изменения;
   - `exp3_resources_after.txt` — ресурсы после изменения файлов `.md`;
   - `exp4_transports.txt` — замеры stdio против streamable-http;
   - `exp5_server_mod.txt` — модифицированный сервер: tool `convert_temperature`, resource `info-city://Astrakhan`, погода;
   - `exp5_server_mod_netfail.txt` — обработка сетевой ошибки в `get_weather`;
   - `exp6_prompt_effect.txt` — ответы модели до и после изменения prompt;
   - `exp_agent_run.txt` и `agent_run.log` — журнал работы агента (задание 8: pre/post `ainvoke`, вызовы инструментов, фильтр).
3. **Изменённый код** — все правки помечены комментариями («ИСПРАВЛЕНО», «ЗАМЕНЕНА», «ИЗМЕНЕНО»):
   - `mcp-server.py` — изменён текст prompt (задание 1), добавлены tool `convert_temperature` и resource `info-city://Astrakhan`, обработка ошибок в `get_weather` (задание 6);
   - `src/data/entry_letter.md`, `src/data/paris_trips.md` — изменённое содержимое ресурсов (задание 2); `src/data/astrakhan.md` — новый ресурс;
   - `src/process.py` — замена модели и ключа, путь к серверу берётся из проекта, сборка всех ресурсов для контекста;
   - `main.py` — задание 8: агент поверх MCP, ресурсы и prompt в `system_prompt`, middleware логирования и фильтрации, нормализация результата инструмента, перехват pre/post `ainvoke`, прогоны экспериментов.

## Как запустить

```bash
make setup                     # зависимости (uv sync)
export MISTRAL_API_KEY=...     # ключ модели, см. примечание ниже
make agent                     # агент с MCP-сервером (stdio)
make mcp                       # сервер в режиме streamable-http (вместе с make inspector)
```

Примечания к окружению (полная версия — в отчёте):

- **Модель заменена.** Исходный код использует `gpt-4o-mini` и требует `OPEN_AI_KEY`; в работе использована `ministral-14b-latest`, ключ задаётся переменной окружения `MISTRAL_API_KEY`. Комментарий о замене — в `src/process.py`.
- **Скрипты экспериментов** `exp1`–`exp6` запускаются как `uv run python <скрипт>.py` и воспроизводят логи из `logs/`.
- Задание 6 выполнено поверх исходного сервера: новый tool, новый resource и обработка ошибок в `get_weather`.

# Исходное описание задания (что было дано)

В данной работе студенты исследуют возможности **MCP сервера (Model Context Protocol)** на основе библиотеки `FastMCP`.

Цель — понять, как работают основные компоненты MCP:

- **Prompt** — шаблоны инструкций для LLM
- **Tool** — функции, которые модель может вызывать
- **Resource** — внешние текстовые данные
- **Transport протоколы** — способы взаимодействия клиента и сервера


## Установка зависимостей

Перед началом работы установите все необходимые зависимости:

```bash
make setup
```

## Запуск MCP сервера STDIO

Для запуска MCP сервера в режиме STDIO используйте команду:

```

```
