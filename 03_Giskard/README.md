# Практическое задание: RAG Security Testing с Giskard

Ноутбук `Тестирование-giskard.ipynb` — пять практических заданий по тестированию LLM библиотекой Giskard.

## Что где смотреть

1. Верх ноутбука — демо-ячейки урока (RAG на PDF, агент, сканирование на GPT-4o). Оставлены без изменений: им нужны `OPENAI_API_KEY`, `TAVILY_API_KEY` и PDF-файлы кейсов.
2. Раздел **«Практическое задание»** (конец ноутбука) — формулировки заданий из постановки.
3. Сразу после — **«Выполнение практического задания»**: самодостаточный блок с исполненными выводами, по разделу на каждое задание:
   - **Задание 1** — собственный тестовый датасет (8 вопросов с эталонами и ключевыми фактами), ответы модели, метрики accuracy (доля правильных ответов), latency (задержка) и correctness (корректность по оценке Giskard);
   - **Задание 2** — полное сканирование `scan()` модели A: 17 найденных проблем с уровнями и примеры проблемных ответов;
   - **Задание 3** — собственные тесты (корректность, безопасность, устойчивость формулировок) и их повтор со строгим системным промптом, сравнение результатов;
   - **Задание 4** — сравнение двух моделей: метрики, результаты сканирования, сводная таблица;
   - **Задание 5** — 16 вариаций запросов (переформулировки, упрощённые и усложнённые версии, шум) и оценка устойчивости.

## Как запустить практическую часть

- Python 3.12; зависимости: `giskard[llm]<3` (версия 2.19.x — с API урока; giskard 3.x из PyPI это другой пакет), `langchain-mistralai`, `datasets<3`, `pyarrow<18`, `pandas`, `nbconvert`, `ipykernel`.
- В окружении нужен `MISTRAL_API_KEY`: модель и LLM-оценщик Giskard подхватывают его из переменной окружения, в коде ключа нет.
- Оценщик Giskard настроен на модель Mistral: `set_llm_model("mistral/ministral-14b-latest", disable_structured_output=True)`.
- Ячейки практической части выполняются сверху вниз без демо-ячеек. Полный прогон со сканами занимает около 75 минут (два полных `scan()` — основное время).
- Воспроизводимость: температура моделей зафиксирована нулём, датасеты и правила проверки заданы в коде ячеек.

## Модели

- A — `ministral-14b-latest`, B — `open-mistral-nemo`. Обе от Mistral AI: других провайдеров в окружении нет, поэтому сравнение — разных линеек одного провайдера.

## Итоги (кратко)

- Модель B точнее и быстрее по метрикам (accuracy 1.00 против 0.88; 15 против 17 проблем скана), но сравнение по скану условно: два детектора при проверке модели B не отработали из-за сбоя разбора JSON оценщиком.
- Общие слабые места обеих моделей: подчинение инъекциям из запроса и ответы на опасные просьбы вместо отказа.
- Системный промпт смещает поведение модели, но не закрывает все риски; к переформулировкам и шуму модель устойчива (robustness (устойчивость) — 0.88).
